# GPT 按钮消息后的工作台展示恢复

生产部署：`.81`，工作台 v45，确认单 v14，schema135。

## 事实与修复

原 GPT 页面中工作台 iframe 仍存在，但其宿主容器为 `display: none`，主对话也没有可见的恢复按钮。v44 仅取消发送后主动切换 inline，未处理宿主发送消息时自行隐藏查看器的路径。

- 统一工作台在消息明确受理后，按发送时的 PiP／全屏模式请求恢复一次，即使最近观测到的模式仍为 PiP。兼容消息入口避免自动滚动切换查看位置。
- 展示与消息送达分别处理；展示拒绝、错误或超时不更改已受理消息的状态、不重发消息。不在普通刷新或手动关闭后持续抢回工作台。发送期间主动切换任务或显示方式优先。
- 用户明确要求重新打开时，允许同一真实 Session 再次 `panel_show`，使用新的展示请求；不创建替代任务、不审批或启动业务。普通阶段推进仍保留单面板。
- 去掉三个 app-only 兼容读取接口在工具列表中的独立模板声明；保留内部读取与嵌入能力。ChatGPT 设置页提示这些私有工具不能渲染组件，但这并不能证明它们是插件刷新失败的唯一原因。

接口依据：[OpenAI 插件 UI Reference](https://developers.openai.com/plugins/reference)。`sendFollowUpMessage` 的 `scrollToBottom` 仅控制滚动；展示通过 `requestDisplayMode` 请求，实际可见性必须另行观测。未使用未公开的宿主接口。

## 验证

- UI 全组 447 项：443 PASS、4 SKIP、0 FAIL。
- MCP 全包 PASS（最终 56.481s）。覆盖宿主在发送途中降为 inline、保持旧 PiP 观测但实际隐藏、三条消息路由、显式重新打开、展示失败不影响送达、任务切换隔离及私有工具声明。
- 浏览器隔离夹具在 `ui/message` 时将 iframe 隐藏；生产 v45 源码收到受理回执后恢复。观测到模拟发送 1 次、恢复 1 次，未连接真实 Core、GPT 或业务数据库。
- 三候选服务隔离启动、资源读取、schema135 和数据库完整性通过。生产三个程序散列与候选一致，Core/MCP/Local MCP ready，最终生产本地核验和远程 bridge_diagnostics 均确认 .81 ready。
- 停止前、停止后、两次部署及原宿主加载后，32 张业务表数量和内容散列均不变；无活动 Run/claim，未审批、准备确认、延续或启动任务。Pi 设置保留。

## 原 GPT 验证限制

用户明确授权一条仅加载 v45 的请求和一次只读分析按钮测试。已在原对话「同步项目会话信息」发送这唯一一条加载请求，GPT 调用 `panel_show`，原 Session/Project/Task 保留。宿主首次加载失败；重试现有组件后工作台可见，但 DOM 标记实际仍为 `task-panel-v44`。

ChatGPT 插件设置中多次点击“刷新工具”均返回“无法更新应用。请重试”；去除私有模板声明后也未成功。刷新原会话后，多条普通助手正文显示“无法加载此回复”；重试同一组件后恢复可见，版本仍为 v44。浏览器日志中的 Statsig 错误不能用于推断插件更新失败的原因。

因此没有在旧 v44 上点击已授权的分析按钮，真实 v45 消息保持展开测试尚未完成。不能宣称原对话已应用新版本或问题已彻底解决。工作台现已恢复可见，后续仍需宿主成功更新插件缓存后复测。
