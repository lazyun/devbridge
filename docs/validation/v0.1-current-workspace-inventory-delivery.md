2. Schema：保持 v43。没有修改 schema、migration 或新增 durable Card entity。SQLite 改动仅为现有 commit presentation 增加无 Git 的读取入口；命令仍走原来的完整校验。

3. Project inventory contract：Core `DevelopmentWorkspaceForSession` 返回共享 `WorkspaceProjection`；公开纯读工具 `development_workspace_get(aiSessionId, featureAreaId?, taskId?)` 同时注册到 GPT MCP 与 Local MCP。`dev_bridge_card_get` 是 app-only 同源入口。Console/HTTP 入口为 `GET /ui/api/development-workspace?project_id=...&ai_session_id=...`，可带 `feature_area_id`、`task_id`、`format=json|text`。

4. Inventory item fields：`id`, `name`, `status`（FeatureArea lifecycle）, `availability`, `reviewStatus`, `commitStatus`, `mergedCommit`, `currentTaskId`, `currentTaskTitle`, `currentTaskStatus`, `currentTaskCommitStatus`, `currentTaskDevIntegrationStatus`, `currentTaskCommitSha`, `currentTaskMergedCommit`, `currentAction`, `updatedAt`, 可选 `readError` 和 `retirement`。current inventory 排除 RETIRED、DECOMPOSED、legacy read-only；不受旧导航的 100 项限制。生命周期与 Review/Task/commit failure 分开表达。

5. Current FeatureArea：有效会话选择保持。首次选择按可执行动作、active Task、最近更新 ACTIVE、首个可用 Area 排序；同时间按 ID 稳定排序。显式选择保持至切换或失效。RETIRING 已选 Area 可以继续展示；RETIRED/DECOMPOSED 退出 current inventory 后自动重选。

6. Current Task：selector 只包含选中 FeatureArea 的 Task。默认 active Task、commit retry Task、最近终态 Task；无 Task 为空。自动选中的终态 Task 会让位于新 active Task；显式选择的有效 Task 在刷新后保持。选择信息仅为进程内 presentation routing 元数据。

7. Single-current identity：`workspace:<aiSessionId>:<projectId>`。移除定时过期重新展示逻辑；show alias、recall、retry 不会因请求 ID 变化再发 MAIN。首次 MOUNT，后续 SILENT/REFRESH。已挂载 Card 的 app read 会认领同一 identity，包括从 Project picker 进入绑定 Project 的场景。

8. 统一的 card-producing/readback paths：两种主卡 show alias；Project open；FeatureArea create/activate/retire/decompose/review start；Task create；Review Approval / Decision respond；Task acceptance 所用 Decision resolver；Task commit retry；FeatureArea commit；取消/恢复；Codex request resolver；development branch 选择/创建。动作结果保留原 structured contract，附共享 workspace refresh metadata。Task/FeatureArea detail read 保持辅助读取，Details 不写 current selection。

9. Refresh：只重读 authoritative presentation，不创建 Task/Review，不修改 Git，不触发 Codex 或 recovery。主卡显示 `refreshedAt`，即最近成功同步时间。使用共享 workspace 的已挂载卡在可见时刷新；隐藏/销毁暂停。跨 Area/Task 切换不会错误套用旧对象的 sourceSequence。

10. Mutation → refresh：Core 完成命令后静默读取 workspace；Card 调用现有命令后原位替换当前内容。Task-first 页面也能提交所属 FeatureArea；Task 自身仍只有原有自动提交与失败重试语义。没有新增手动 Task 初次提交按钮。

11. Error/fallback：Project read 失败保留原 Card、原成功同步时间，显示“刷新失败”。单个 Area 的 workflow/commit 读取失败只标记该 item 的 readError；其他 Area 继续返回。选中 detail 失败不丢弃 inventory。命令成功后的 readback 失败设置 `projectionRefreshRequired`，不会把成功命令改成失败。

12. JSON/Text/Console/Card parity：同一 DTO、同一 selection reducer、同一 `CurrentAction`。`RenderWorkspaceText` 展示 Project/Branch、全部 FeatureAreas 的分层事实、当前 Area/Task/Action。HTTP JSON/Text 已补 parity 验证；GPT 与 Local MCP 公开同一读取工具。WebUI 只增加必要读取入口，未重做页面布局。

13. Performance：FeatureArea 全量读取一次；Task 列表读取一次并按 Area 分组；每 Area 使用有界 durable guidance/commit 查询。inventory 不执行 Git、工作区扫描或 Codex 查询；仅选中对象保留原有深层 presentation 读取，深层开销不随 Area 数量增长。`CommitInventoryCapability` 与 `CommitInventoryFacts` 显式排除 live Git 定位、校验和诊断。测试覆盖 106 个 Area、单个 detail 调用，以及 Git 被替身拦截时 inventory commit 仍能读取。不是逐 Area 调深层 runtime 的 N+1。
