# WebUI 内容与布局修正（2026-10-22）

用户反馈：WebUI 多处布局、中文文案或内容展示不正确。本次核查使用现有 skeleton 项目和已完成任务“统一 Core 与 pkg/flow 依赖边界”，仅浏览真实业务数据，没有重新执行、批准、验收或合入任务。

## 已定位并修正

| 页面 | 实际问题 | 修正 |
| --- | --- | --- |
| 任务列表 | 项目摘要有 2 个任务，列表却显示 0；失效的旧领域筛选仍被发送，选择器却显示“全部” | 先核对当前项目筛选再请求列表，同时同步旧/新筛选状态、清零分页、保存修正，增加清除入口及说明；不完整任务清单不擅自判定历史分支失效 |
| 任务列表与详情 | Done、SUCCEEDED、COMPLETE 等直接混入中文界面 | 按语言展示任务阶段、状态、进度步骤；原始状态继续保留在数据和诊断属性中，终态优先展示 |
| 任务详情概览 | 技术 ID、执行回执占据首页，缺少明确的代码和验证结果 | 增加任务结果区，显示实际实施方式、提交、开发分支集成与验证摘要；原始需求和诊断分别折叠 |
| 任务结束后的操作 | 已完成任务仍展示不可用的“终止执行” | 隐藏终态不可用操作；可用的提交重试、现有待决事项和未确认回执仍保留 |
| 审查与运行历史 | FAST、SUCCEEDED、UNAVAILABLE 等直接展示；长 Run ID 挤占内容 | 翻译深度和已知状态；运行入口保留准确 ID 和 title，显示可读名称 |
| 领域详情 | 已全部合入后仍显示“等待 Task 完成验证、验收和代码提交” | 只在无活动任务、已提交、交付已结清且无错误/恢复状态时，移除该过期展示原因；不改 canonical capability 或业务状态 |
| 领域交付 | 表格展示 Repository/Member 内部 ID、COMPLETED，菜单缺失翻译 | 主区展示仓库名称、中文状态、合入提交；成员身份等仍在诊断详情中；上下文重置移到上下文折叠区，保留创建任务入口 |
| 运行会话 | AI 逻辑审查被笼统描述为“尚无 Codex Thread” | 有无外部会话按真实 thread 记录展示，不推断执行方；用途/状态中文化，保留准确运行标识和开始时间 |
| 运行正文 | 首次选择运行时标题已载入，正文却长期留白；切换指令再返回也无法恢复 | 尚未建立内容容器时完整挂载；非会话标签记录自身模式，返回会话重新挂载；增量更新仍保留同一条记录身份 |
| 布局 | 筛选器挤在一行，结果与诊断缺少层级 | 筛选器使用可换列网格；结果使用独立信息区，窄屏改为单列；缩减项目页多余留白 |
