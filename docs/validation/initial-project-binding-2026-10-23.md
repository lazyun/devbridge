# 首次项目绑定修复

## 复现

生产新会话尚未绑定项目，没有 PROJECT_SETUP 确认单。ChatGPT 提示用户在右侧面板选择项目，但组件只列候选名称，还需通过“发起操作”请求 GPT 准备。未绑定时切换标签或打开操作会调用仅支持已有工作区的 render，实际页面显示 `Dev Bridge Card is unavailable.`；会话读取完成后的按钮也缺少重新更新资格。

## 修复

- 未绑定的统一面板直接提供“选择项目”。仅用户点击后调用现有 `project_setup_prepare / SELECT_PROJECT`，正式确认表单仍在原面板后续操作中，由用户明确选项并确认。
- 重用现有 Core 准备、可用选项、提交和回读合同；不增加业务接口、不自动选择单候选、不修改个人设置。`project_setup_prepare` 增加 App 可见性，组件以进程内点击令牌、原 Session、SELECT_PROJECT 目的和准确读取状态限制调用；可见性不是权限，Core 原有资格和身份校验保留。
- 首次项目选择不依赖 GPT 消息或第二张会话卡片。已有 PENDING/PARTIAL/UNKNOWN 表单复用；准备回执不确定时保留相同 requestId，不自动提交。空列表、读失败、身份不符时不可准备。
- 未绑定页面本地重绘继续显示项目页；异步读完会重新检查按钮可用性。正式确认后回读同一 Session，并在原面板进入工作区。
- 组件更新为 v30，旧 v29 URI 仍可读取最新资源；服务更新为 .59，schema 131。原 Codex 工程执行边界 .58 保留。
