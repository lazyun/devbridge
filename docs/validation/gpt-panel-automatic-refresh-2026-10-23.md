# GPT 右侧面板自动刷新状态保持（2026-10-23）

版本 `.53`，组件 `ui://devbridge/card/task-panel-v26`，schema 131。

## 问题与修复

原面板每五秒回读后重建 DOM，未保存普通展开区、报告层级、焦点和选区。操作列表还会绕过原来的编辑保护直接重绘。确认项只记录打开动作，主动关闭后又在下一轮自动打开；滚动位置在元素连入页面之前恢复，实际偏移也可能尚未收到 scroll 事件。

- 按准确 Session、Project、FeatureArea、Task 和 TaskDefinitionRevision 保存展示状态。顶部导航共享展开状态，三个操作页签分别保存展开层级和滚动位置；报告还绑定准确 Run/Execution 结果身份。
- 重绘前读取实际滚动位置，挂载后再恢复。保留同一准确确认的控制器和宿主元素；只恢复可见状态、焦点和光标，不从旧 DOM 复制表单值或授权。
- 主动收起的确认项在刷新后保持收起；新出现的确认仍可发现。确认版本、内容哈希、资格或任务定义变化后，旧控制器失效并按新事实重新展示；历史记录仍为只读。
- 原生下拉框及报告文字选择期间暂缓被动绘制；焦点离开或选择结束后补绘。确认列表的新鲜资格已更新，即使暂缓绘制，失效确认也立即 inert，旧控制器的 canInteract 同样拒绝。
- 普通文本编辑不阻断整个悬浮面板读取新事实。按已存在的准确草稿恢复文本，保持焦点、光标和文本框选区。新运行只清理对应报告缓存，不再无条件关闭需求编辑区。
- v25 及更早资源 URI 保持兼容；已缓存的宿主组件需要重新展示，点击旧组件内部刷新只能更新数据。
