# Desktop 控制台工作台（2026-10-26）

此嵌入式方案已被同日的 [Desktop 独立任务工作台](desktop-native-console-2026-10-26.md) 替代。

Desktop 原有摘要依赖 Core 的全局项目选择，并把 snake_case 字段按 camelCase 读取；出现“0 个仓库”“没有运行”且没有任务入口，不能代表实际任务状态。本次用 Core 正式工作台替换独立摘要投影与重复轮询。

## 展示与操作

- 项目与开发分支选择、待处理决策、运行时权限请求、异常与阻断。
- 任务标题、当前阶段、代码提交与交付状态，以及审查/验证证据。
- 任务详情及 Core 当前提供的操作、运行会话、项目资料和诊断。
- 项目可信执行/联网授权设置仍按原有显式保存流程执行。
- 重载工作台、在浏览器打开、Core 不可用时启动服务及恢复后的重连。

内嵌页面复用 Core 当前数据、操作与门禁，不在 Desktop 建立第二套任务状态机。项目查看选择保存于本地，不改变 GPT 会话绑定。每秒 Desktop 状态更新仅更新连接提示，不重新创建 iframe，因此保留表单、抽屉、滚动及订阅；点击已选中的 Desktop 导航也不重建页面。

内层导航改为保留文字的紧凑工具栏，适配原生窗口宽度。运行会话页面保留原有专用布局，样式不受控制台覆盖。

## 边界验证

所有 Core API 仍须同源文档 token；连接目标来自实际托管/附着的 Core 回环地址。转发重建宿主请求，不转发浏览器 Cookie、Authorization、Origin 或文档 token。新增 PUT 仅允许精确的项目 execution-authorization 路径，不开放通用 /v1 写入。测试覆盖缺失/错误 token、外部来源、路径编码分隔符、非法方法拒绝及任务动作查询参数和请求正文完整转发。

## 测试与限制

前端 58 项测试通过，包括文档在重复状态更新中保持不变、停止恢复时重载、运行实例变化、原有会话布局及错误恢复入口。

原有 Codex executable-resolution 测试起初失败：公共对抗夹具的逃逸软链接被当前复制策略拒绝，且模拟后端缺 config/read、mcpServerStatus/list 和 activePermissionProfile 响应。只在该测试建立有效提交并补齐模拟协议，增加错误时尽早失败；不修改全局夹具或产品权限校验。修正后定向测试通过。

Desktop 全模块 `go test ./...` 通过（主包 27.346s），`go vet ./...` 与 Wails 原生打包通过。已更新并重启实际 Desktop；原生界面展示 skeleton 的 1 个仓库、19 个模块、3 个任务，并可打开待验收任务结果和操作区。“延续任务”可用，“完成并合入”按必需证据门禁禁用。只做读取验收，未触发生产任务动作。部署前后 32 张业务表哈希一致，数据库 schema135、integrity=ok，项目授权表仍为空。

完整结果及原生验收见 `build/desktop-console-20261026/`。本次只更新 Desktop，Core/MCP 三个已部署二进制保持 .79。不会代用户确认、审批、启动运行或修改项目权限。

最终原生验收还点击了“重新加载工作台”：同一 Task 和概览标签恢复，任务标题、验证缺口和当前操作继续可见。保留最终任务操作区供用户继续；没有提交任何业务动作。
