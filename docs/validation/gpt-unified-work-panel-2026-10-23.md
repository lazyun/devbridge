# GPT 统一工作面板改版（2026-10-23）

用户要求 GPT 右侧面板收口全部执行流程中的操作。此前只有部分审批入口在面板中：创建、修订反馈、运行问题、权限选择和报告查看仍有断点。

## 最终实现

版本 `.50`，资源 `ui://devbridge/card/task-panel-v23`，schema 131；旧 v22 URI 继续返回兼容组件。组件策略更新为 `SINGLE_PANEL_WITH_EXPLICIT_USER_DECISIONS`，外部模型合同同步去除“面板没有任何权限按钮”的冲突描述。

- 顶部集中显示对象身份、阶段及总进度；下方“后续操作 / 结果与报告 / 历史操作”分别承担处理、阅读和只读归档。
- 面板直接收集需求、创建类型与修订意见。GPT 仍负责工程内容和 immutable prepare；正式审批保留原隔离组件、固定身份和原 Core 校验。终态任务允许发起独立新工作，不重开旧任务。
- Session 提案 feed 增加原 prepare requestId 与冻结标题。只有本次显式请求的创建提案进入当前处理区；旧创建提案保持只读历史，未消费/取消/过期任何旧提案。
- Core 当前能力按 action/完整 target、Task/revision、领域和新鲜资格核对；恢复/取消/重试/合入等后续处理仍走原 canonical 合同。不可用理由默认折叠。
- GPT 审查授权恢复需要面板内明确确认，再刷新准确 Core 资格并逐字段匹配 observed upper version；仅恢复原 Review。已授权 GPT 审查、文件实施分别提供实际工作与正式提交请求。
- 已结束的 Codex/Pi 审查即使没有正式报告，也可从 `analysisState=REQUIRED` 进入 GPT 正式分析提交；项目检查保留同样的准确 Run 分析入口。实施/验证分析沿用原结果与报告合同。
- 原始 Codex 问题保留原始选项且无默认选择，用户确认最终回答后直接调用 canonical hash preparation / UserDecision submit。该 Core 提交已负责准确记录和后端投递，面板不再额外 respond。保密回答不发给 GPT、不写 widget state。运行分区中的问题及 UNKNOWN 也保留准确入口；未知回答不自动重发，等待/取消与原 RESPOND 的本地回执隔离。
- 运行权限先独立读取完整原文，提交前再次核对准确 Approval/Run、原文和允许选择；遗留 CANCEL 整个 Run 的语义单独确认。受理、冲突和未知回执分别展示，不把取消 ACK 当终态。
- 结果按准确操作读取，拒绝外部 Task/Run 报告；历史控制器保持 `.49` 的只读和旧句柄失效保护。
- 单面板接管运行问题后，不再触发旧的重复对话 wakeup；没有 PiP 的宿主使用同一内嵌工作面板。
