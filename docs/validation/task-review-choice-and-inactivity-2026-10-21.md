# 任务审查方式与无活动提示验证（2026-10-21）

本记录覆盖当前工作区的定向验证，不代表整体发布验收通过。

## 已实现行为

- Task 创建卡片由用户主动选择「AI 读取文件并提交审查报告」「Codex 审查」「不审查，进入实施确认」。新审查提案提供两个执行方的完整指令；卡片不默认选择执行方。
- AI 文件审查明确由发起对话继续，连续五分钟没有 Bridge 可验证活动时给出提示。状态读取和刷新不计入活动；已取消、已完成及恢复等待状态不显示活动停滞警告。
- 原生审查详情、历史和执行诊断显示实际执行方。Run 页面仅在有真实线程时提供会话入口。
- `NONE` 创建任务时不创建 Review、Execution 或 Run。`CONFIRM_IMPLEMENTATION` 单独冻结完整实施与验证定义；`START_APPROVED` 再确认本次运行配置。当前跳过审查路径支持单个明确 Repository 的 Coding 实施。
- 数据库新增 schema v126，保留跳过审查与实施确认回执。旧 `startReview: false` 且未指定 `reviewMode` 的请求仍表示延后审查，原请求回放不添加新字段。

## 通过的检查

- 新增 Go 集成检查：跳过审查后的独立实施确认、响应丢失后按原回执恢复、禁止直接启动及修改已确认定义、拒绝改变已消费的选择、AI 审查不依赖 Codex 配置、独立启动的运行配置与准入回执、在实施卡片中才选择仓库的路径。
- Go 展示与协议检查：五分钟临界点、终态不提示、读取不制造活动、审查方式枚举与回执身份、两种执行方的准备约束、当前文档合同。
- 50 项 JavaScript 检查通过，覆盖完整卡片脚本、三种选择、缺失方式、配置切换、结果未知与重试、历史请求恢复、原生审查历史及真实会话入口。
- 原生审查详情和运行信息的 4 项定向 JavaScript 检查通过。
- 根模块生产代码 `go build -p 1 ./...` 通过；受影响六个 Go 包的 `go vet -p 1` 通过。
- 真实 MCP 回环协议样本已按当前卡片脚本重新采集；检查仅使用临时数据库与测试运行时。
