# 在 ChatGPT 中悬浮查看任务进度

让 GPT 展示指定 Task 的工作区卡片，点击 **悬浮查看**。卡片会请求 ChatGPT 的 PiP 显示方式，在继续对话时保留任务名称、流程阶段、待处理事项与最后读取时间。

审查结束且结果可读后，卡片提供 **让 GPT 分析审查结果**，包括收起入口、紧凑进度视图及具体历史 Review 的结果操作区。点击后让当前对话中的 GPT 读取这次准确 Review 的完整结果及其引用的正式报告，再分析结论和依据、拟修改文件与范围、风险和遗漏、验证是否充分和可执行，以及是否建议批准和应先解决的问题。分析完成后由你决定是否批准，点击本身不批准审查或启动实施。

等待审批时，当前任务卡片还显示 **审批确认**、**要求修改方案** 和 **取消任务**，以 Core 当前返回的操作资格为准。点击审批确认会让 GPT 按准确 Review、Decision 和定义修订读取原报告、准备 `APPROVE` 正式确认卡片，最后由你在正式卡片提交；这不会自动启动实施。要求修改会先收集你的具体意见。取消任务先在卡片中再次确认，点击“确认取消任务”后向对话发送明确取消请求，由 GPT 核对最新 TASK 取消资格并报告回执。消息已发送不代表业务已经完成。

历史详情或已失效的决策不显示这些入口。操作准备被拒绝时会保留准确错误，不会自动修改验证方案、降低必需检查或添加豁免。

未结束或结果不可读的审查不显示此入口。历史审查固定使用所点击的 Review ID，不会换成当前最新 Review；结果不可读或身份冲突时说明问题并停止。你仍可点击“查看审查结果”，或用“复制分析指令”在普通对话中手动请求相同分析。

标签页、全屏和 PiP 中的操作始终保留当前显示方式。发送分析、准备审批、请求修订或取消后都不会自动回到对话卡片；OpenAI 兼容消息接口也不会强制滚动对话。需要阅读 GPT 分析时可自行查看对话，只有手动点击“返回对话”才请求切换为内联卡片。发送失败或超时时不自动重试，并提供可手动发送的分析指令；先检查对话是否已收到，再决定是否手动发送，避免重复。审查结束会使分析入口可用，挂载、刷新和轮询不会自行发送分析请求。无卡片客户端仍可在普通对话中明确请求分析具体 Review。

悬浮窗内可刷新进度，点击 **返回对话** 只恢复原来的内联卡片，不发送消息。审批与实施方案由对话准备；新版面板可在下方独立正式确认项中由用户提交。上方进度展示和刷新不会批准任务或取得文件写入授权。

悬浮展示期间会定期只读刷新当前任务，包括等待批准和等待下一步操作的阶段。审查或某次 Run 结束不会提前关闭任务进度；Task 正式成功、失败或取消后，也会保留当前展示和结果，不自动关闭标签页或切回内联卡片。隐藏页面或关闭组件会停止刷新。刷新失败时保留已有进度并显示提示和最后成功读取时间。

PiP 是 **ChatGPT 内的悬浮视图**。实际显示方式由宿主决定；手机端可能以全屏呈现，仍可返回对话。不支持 PiP 的客户端继续使用内联卡片；不渲染卡片的客户端仍可通过普通对话和只读工具查询任务。首次更新后需要重新展示卡片，已挂载的旧卡片不会自动换成新组件。

开发模式连接可能缓存旧组件。服务更新后若新卡片仍没有悬浮入口，可在 ChatGPT 的插件设置中打开 Dev Bridge，执行“刷新工具”，再让 GPT 返回一张新的任务卡片。仅刷新页面可能仍加载旧脚本。

悬浮进度与 [Task Events 通知](task-events-and-codex-history.md) 相互独立。关闭悬浮窗不会取消既有通知订阅；页面关闭后也不能把卡片轮询当成后台通知。

官方接口与宿主行为见 [Plugin UI reference](https://developers.openai.com/plugins/reference) 和 [UI guidelines](https://developers.openai.com/plugins/concepts/ui-guidelines)。组件同时声明 `inline`、`pip` 和 `fullscreen`；根据宿主能力使用显示模式请求，并兼容 `window.openai.requestDisplayMode`。

## 在同一面板处理后续确认

新版悬浮面板上方固定总进度，下方是可上下滚动的“后续操作”。GPT 为当前 Task 准备好正式确认后，它会自动出现在列表；展开该项即可查看完整方案、选择运行配置并正式确认，无需回到对话寻找另一张卡片。

待确认及结果待核对项优先显示，历史项折叠。每项都有独立确认记录与版本；“确认已完成”表示该操作回执完成，任务是否完成仍以上方 Core 总进度为准。已过期或已替换的项可以查看，但不能按旧内容推进。操作列表读取失败时会明确提示，不会推测已有选择。

确认之后保持当前悬浮或标签显示方式。上方继续展示同一个 Task，下方原项更新为回执；需要下一次审批时，新项进入同一列表。普通对话、无悬浮支持的客户端仍保留原来的独立确认卡片。任务创建前尚无 Task 身份的项目、领域和新任务创建确认继续使用独立卡片；创建后才集中到该任务面板。
